# OrphaCare Web

React single-page app for OrphaCare, built with React 19, Vite 7, TypeScript, TanStack
Router and Tailwind CSS 4.

## Prerequisites

- Node.js 22+
- pnpm 10+
- The [OrphaCare API](../backend/README.md) running locally

## Setup

```bash
cd frontend
pnpm install
cp .env.example .env       # or create .env with the variable below
pnpm dev                   # http://localhost:5173
```

## Environment variables

| Variable | Required | Purpose |
|---|---|---|
| `VITE_API_BASE_URL` | yes | Base URL of the API, e.g. `http://localhost:8000`. The `/api` prefix is appended by the client. |

Read and normalised in [src/config/env-constant.ts](src/config/env-constant.ts), which
strips trailing slashes, adds a missing protocol and warns in development if the value
cannot be parsed as a URL.

## Routes

Routing is file-based via TanStack Router. Files under `src/routes/` map to URLs, and
`src/routeTree.gen.ts` is generated by the router plugin — **never edit it by hand**.

| Route | Page |
|---|---|
| `/` | Landing page: hero and grid of children awaiting adoption |
| `/about` | About the organisation |
| `/children/$childId` | Child profile and adoption request entry point |
| `/reports` | Missing-child reports |
| `/reports/$reportId` | Report detail |
| `/donations` | Donation form and impact sidebar |
| `/volunteers` | Volunteers |
| `/dashboard` | Protected; renders the admin or user dashboard by role |
| `/sign-up`, `/sign-in` | Registration and login |
| `/verify-email` | Email verification landing page |
| `/forgot-password`, `/reset-password` | Password recovery |

## Project structure

```text
src/
  routes/                  File-based routes; routeTree.gen.ts is generated
  features/                One folder per domain
    <feature>/api.ts       Typed API calls for the feature
    <feature>/types.ts     Request and response types
    <feature>/components/  Presentational components for the feature
  components/
    ui/                    shadcn-style primitives
    icons/                 Icon components
    ProtectedRoute.tsx     Auth and role guard
  common/components/       Navigation bar, footer, modal, not-found
  hooks/                   useCustomQuery, useCustomMutation, useDebounce, useThemeStore
  lib/api.ts               axios instance: bearer token injection, 401 refresh retry
  config/                  API base URL and axios factory
  store/auth-store.ts      Persisted Zustand auth state
  test/                    Test setup
```

## Conventions

**Data fetching.** Server state belongs to TanStack Query through the `useCustomQuery` and
`useCustomMutation` wrappers; client state belongs to Zustand. Do not mirror server data into
the store.

**API calls.** Every request goes through a feature's `api.ts` — components never call axios
directly. This keeps request paths and response types in one place per feature.

**Auth.** [src/lib/api.ts](src/lib/api.ts) attaches the access token to each request and, on a
`401`, refreshes once and retries the original request; a failed refresh clears the session.
`ProtectedRoute` redirects unauthenticated visitors to `/sign-in` and can additionally
restrict a route to a set of roles.

**Forms.** React Hook Form with a Zod resolver. The validation schema is the source of truth
for the form's types.

**Styling.** Tailwind utility classes with shadcn-style primitives in `components/ui`. Prefer
composing an existing primitive over introducing a new component library.
